# Initial UI and preferences observations

Observed on macOS 27.0.1 (build 26A434) in the installed TextEdit application on 2026-10-17. These are a single initial-state observation, not a full behavioral verification.

Launching the application presented the standard macOS Open panel in a TextEdit iCloud location. It offered a new-document action and a settings action for the panel. Choosing new document opened a blank untitled document. The document window displayed the formatting controls above the editing area, with bold, italic, underline, strike-through, foreground and background colors, font family/style/size, paragraph alignment, list style, and line spacing. A horizontal ruler was visible. The initial blank document used Helvetica at 12 points in the toolbar. The ruler showed a 0–8 inch scale with half-inch marks. A formatting ruler and formatting toolbar were visible; exact window frame dimensions and toolbar customization behavior remain unmeasured.

The application menu exposed an About action, Settings, Services, hide/show commands, and quit commands. The document window had File, Edit, Format, View, Window, and Help menus.

The Settings window has two sections. The new-document section initially selected rich text and offered plain text as an alternative. It included a wrap-to-page option (off), a plain-text starting size of 96 characters by 30 lines, separate plain-text and rich-text font controls, author/organization/copyright fields, and options for showing the ruler (on), checking spelling while typing (on), grammar checking with spelling (off), automatic spelling correction (on), smart quotes (on), smart dashes (on), smart links (off), text replacement (on), data detection (off), smart copy/paste (on), smart punctuation limited to rich-text documents (on), and spelling correction limited to rich-text documents (off). The pane shows Menlo Regular 11 for plain text and Helvetica 12 for rich text; the blank rich-text document's toolbar also showed Helvetica 12. The Settings pane indicates that some writing assistance and substitution options can be changed for individual documents through the Edit menu, while the rich-text-only switches apply to newly opened documents and after converting to plain text.

The open/save section initially had code-display options for RTF and HTML turned off. Adding a `.txt` extension to plain-text saves was on. The default open and save encodings were both Automatic. HTML export initially preserved whitespace, selected a strict HTML 4.01 document type, used embedded CSS, and selected UTF-8 encoding.

Before opening Settings, the user defaults database contained only navigation-panel sizing and a last-root-directory bookmark. Exact preference keys and behavior after changing the controls are recorded in `PREFERENCE-KEYS.md`.
